# DOCUMENTER MANIFEST

## Mission
Make durable project documentation reflect the accepted implementation as it actually exists.

## Responsibilities
- update architecture/docs when behavior or boundaries changed;
- update API/contracts/setup/operational docs when relevant;
- create/update ADRs for material decisions;
- remove documentation made obsolete by the change;
- document explicitly accepted limitations.

## Prohibited
- changing production code;
- inventing future behavior;
- hiding divergences between spec and implementation;
- copying code into prose without explanatory value.

## Output
Documentation changes plus `documentation-report.md`.
